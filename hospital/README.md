# Hospital — интерфейс на Tailwind CSS

Frontend-приложение системы управления пациентами **без бэкенда** на Next.js App Router, React и TypeScript. Интерфейс оформлен с помощью Tailwind CSS. Команда: **Бекаман, Данияр, Далел**.

[Репозиторий GitHub](https://github.com/diko-cat/maz) · [Техническое задание](TZ.md) · [Корневой README](../README.md)

## Локальный запуск

Команды выполняются из папки `hospital`:

```bash
npm ci
npm run dev
```

Открыть [http://localhost:3000](http://localhost:3000). Если сервер выберет другой порт, использовать адрес, напечатанный в терминале. Рекомендуется Node.js 24 LTS и npm. Точные версии зависимостей зафиксированы в `package.json` и `package-lock.json`.

## Маршруты

| Маршрут | Реализация |
| --- | --- |
| `/` | Главная страница на Tailwind CSS |
| `/tailwind` | Tailwind CSS |

Оба маршрута открывают один интерфейс с разделами обзора, пациентов, врачей и записей на приём.

## Структура исходников

- `components/clinic-app.tsx` собирает оболочку, экраны и диалоги.
- `components/use-clinic-dashboard.ts` управляет разделами и действиями пользователя.
- `components/clinic-shell.tsx` и `clinic-notices.tsx` содержат навигацию, заголовки и уведомления.
- `components/clinic-dashboard.tsx` выбирает экран из модулей `components/dashboard/`.
- `components/clinic-dialogs.tsx` содержит формы пациента и записи, а также общий диалог.
- `lib/data.ts` хранит демонстрационные данные и правила проверки форм.
- `lib/selectors.ts` вычисляет результаты поиска, сортировку и показатели обзора.
- `lib/storage.ts` проверяет и читает сохранённые данные, `lib/hospital-store.ts` связывает их с React.
- `lib/types.ts` описывает общие данные и интерфейсы компонентов, `lib/format.ts` отвечает за отображение.
- `app/globals.css` подключает Tailwind; оболочка и экраны используют utility-классы, общие стили форм в `app/styles/forms.css` собраны через `@apply`.

## Возможности текущего этапа

- Обзор с показателями, рассчитанными на основе текущих данных.
- Пациенты: поиск по ФИО, фильтр по полу, сортировка по ФИО или дате регистрации.
- Добавление и редактирование пациентов с проверкой полей; удаление с подтверждением.
- Врачи: демонстрационный список и поиск по имени или специальности.
- Записи на приём: просмотр, создание с проверкой занятости врача и отмена.
- Сохранение пациентов и записей в браузере между посещениями.
- Профиль администратора с редактированием имени, должности, электронной почты и телефона; данные сохраняются в браузере.

Данные хранятся в `localStorage`: они сохраняются после перезагрузки в том же браузере и на том же адресе. Для другого устройства, браузера или порта используется отдельное хранилище. Очистка данных сайта в браузере удаляет локальные изменения и возвращает начальную демонстрацию при следующем открытии.

Это учебная демонстрация на вымышленных данных. Дополнительно доступен Express API для страницы врача, услуг, расписания, записей и отзывов. API использует JSON-файл `server/data/db.json`; это учебное хранилище без авторизации, не предназначенное для медицинских данных реальных пациентов.

## Express API

Установите зависимости и запустите отдельный API сервер из папки `hospital`:

```bash
npm install
npm run api
```

По умолчанию сервер доступен на `http://localhost:4000`. Порт можно задать через `API_PORT`, разрешённые CORS origins — через `CORS_ORIGIN` (несколько адресов разделяются запятыми; по умолчанию разрешены все origins). Обработка расписания использует фиксированные слоты с 09:00 до 16:30 с шагом 30 минут.

### Примеры запросов

```bash
# Данные врача
curl http://localhost:4000/api/doctor

# Медицинские услуги
curl http://localhost:4000/api/services

# Свободные и занятые слоты
curl 'http://localhost:4000/api/schedule?date=2026-12-01'

# Создать запись
curl -X POST http://localhost:4000/api/appointments \
  -H 'Content-Type: application/json' \
  -d '{"patientName":"Айжан Садыкова","phone":"+77001234567","serviceId":"consultation","date":"2026-12-01","time":"10:00"}'

# Отзывы: страницы по 10 записей (параметры page и limit)
curl 'http://localhost:4000/api/reviews?page=1&limit=10'

# Добавить отзыв
curl -X POST http://localhost:4000/api/reviews \
  -H 'Content-Type: application/json' \
  -d '{"patientName":"Айжан Садыкова","rating":5,"text":"Очень внимательный врач."}'
```

API разложен на `server/routes.js`, `server/controllers.js`, `server/validators.js`, `server/middleware.js` и `server/store.js`. Записи с совпадающими датой и временем отклоняются с HTTP 409.

## Проверки и production-сборка

```bash
npm test
npm run lint
npm run typecheck
npm run build
npm run start
```

`npm test` проверяет даты, валидацию пациентов, конфликты расписания, поиск, сортировку, показатели обзора и совместимость браузерного хранилища. Последняя команда запускает уже собранное приложение. Проверки выполняются после установки зависимостей.

`npm run typecheck` сначала генерирует типы маршрутов Next.js, затем проверяет весь TypeScript-код без компиляции файлов. `npm run check` последовательно выполняет lint, тесты, проверку типов и production-сборку; при ошибке выполнение останавливается.

В VS Code, открытом в корне `maz`, `Ctrl+Shift+B` запускает все проверки. Через **Terminal → Run Task → Hospital: dev** можно запустить сервер разработки. Инструкция по Commit и Push находится в [корневом README](../README.md#commit-и-push-в-vs-code).

## Проверка при сдаче

1. Открыть `/` и `/tailwind`, проверить основные разделы.
2. Найти пациента, применить фильтр по полу и изменить сортировку.
3. Добавить пациента, изменить его данные, проверить отмену и подтверждение удаления.
4. Отправить форму с ошибками и проверить сообщения.
5. Создать запись, проверить занятое время врача и отмену записи.
6. Обновить страницу и перейти между `/` и `/tailwind`: данные должны сохраниться.
7. Проверить узкий экран и пустые результаты поиска.
